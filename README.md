## Общее описание

DGVT принимает имя npm-пакета и параметры анализа зависимостей.
Этапы работы зафиксированы отдельными коммитами.

## Установка и запуск

Для запуска нужны Python 3.10+, оболочка sh и Graphviz с командой
`dot` в PATH. Для показа SVG нужен браузер. Сборка не требуется.

Из корня проекта:

```sh
./run.sh --help
./run.sh --package is-odd --version 3.0.1
```

## Этап 1. Минимальный CLI и конфигурация

На первом этапе приложение проверяло параметры и печатало конфигурацию.
Вывод конфигурации относится к коммиту первого этапа.
Для URL проверялся формат адреса, для тестового файла — читаемость.

### Структура проекта на этапе 1

```text
.
├── README.md
├── .gitignore
├── run.sh                    # запуск CLI
├── requirements-dev.txt      # pytest
├── src/
│   └── main.py                # разбор аргументов, проверки и вывод
├── examples/
│   └── repository.json       # пример локального репозитория
└── tests/
    └── test_cli.py            # проверки через run.sh
```

### Параметры

| Параметр | Назначение |
| --- | --- |
| `--package NAME` | Обязательное имя пакета, например `is-odd` или `@scope/pkg`. В тестовом режиме — только буквы A–Z. |
| `--repository SOURCE` | Базовый HTTP(S)-адрес без учётных данных, запроса и фрагмента. По умолчанию `https://registry.npmjs.org`. В тестовом режиме обязателен путь к читаемому файлу. |
| `--test-mode` | Переключает источник на локальный тестовый файл. |
| `--version VERSION` | Точная версия npm-пакета, обязательна в сетевом режиме. С `--test-mode` не используется. |
| `--ascii` | Флаг вывода ASCII-дерева. На этапе 1 выводится его значение. |

### Примеры работы

```sh
./run.sh --package is-odd --version 3.0.1 --ascii
```

```text
package=is-odd
repository=https://registry.npmjs.org
test_mode=false
version=3.0.1
ascii=true
```

```sh
./run.sh --package A --test-mode --repository examples/repository.json
```

```text
package=A
repository=examples/repository.json
test_mode=true
version=
ascii=false
```

### Обработка ошибок

При неверных параметрах приложение печатает сообщение в stderr и
завершается с кодом 2. Успешный запуск завершается с кодом 0.

```sh
./run.sh --version 3.0.1                                  # нет имени пакета
./run.sh --package 'Bad Name' --version 3.0.1              # неверное имя
./run.sh --package is-odd                                 # нет версии
./run.sh --package is-odd --version '^3.0.1'               # диапазон версий
./run.sh --package is-odd --version 3.0.1 --repository ftp://example.org
./run.sh --package A --test-mode                          # нет пути к файлу
./run.sh --package A --test-mode --repository missing.json
./run.sh --package is-odd --version 3.0.1 --test-mode=true # флаг без значения
./run.sh --package is-odd --version 3.0.1 --ascii=true     # флаг без значения
```

## Этап 2. Прямые зависимости npm

На этом этапе CLI запрашивал метаданные по адресу из `--repository` и
читал поле `dependencies` указанной версии. Каждая строка содержала
имя зависимости и её ограничение версии. Строки были отсортированы
по имени. Для пакета без зависимостей выводилось сообщение
«Прямых зависимостей нет.». Этот формат вывода относится к коммиту этапа 2.

Настройки CLI описаны в этапе 1. Сетевые запуски требуют доступа к реестру.
На этапе 2 тестовый режим не поддерживался.

### Структура проекта на этапе 2

К структуре этапа 1 добавились два файла:

- `src/registry.py` — `fetch_metadata` запрашивает и разбирает JSON,
  `get_dependencies` выбирает нужную версию и возвращает её зависимости.
- `tests/test_registry.py` — тесты чтения метаданных с подменой ответа.

### Примеры запуска

```sh
./run.sh --package is-odd --version 3.0.1
```

```text
is-number ^6.0.0
```

```sh
./run.sh --package is-number --version 7.0.0
```

```text
Прямых зависимостей нет.
```

### Обработка ошибок

Отсутствующий пакет или версия, ошибка HTTP или соединения, тайм-аут
и неверный ответ реестра дают сообщение в stderr и код завершения 1.
Ошибки параметров по-прежнему дают код 2.

```sh
./run.sh --package is-odd --version 999.0.0
```

```text
DGVT: версия is-odd@999.0.0 не найдена
```

## Этап 3. Транзитивный граф

DGVT строит граф обходом в ширину (BFS) без рекурсии. Узлы добавляются в
очередь один раз, поэтому циклы не зацикливают обход, но остаются в списке
рёбер. Каждая строка показывает связь `пакет -> зависимость`. Если у корня
нет зависимостей, выводится только его имя.

В сетевом режиме вершина имеет вид `имя@версия`. Для точной зависимости
используется указанная версия, включая точную prerelease. Для диапазона
выбирается наибольшая подходящая стабильная версия. Поддерживаются `^`,
`~`, сравнения, их комбинации, `||`, диапазоны через дефис, неполные
версии и шаблоны `*`/`x`. Теги и ссылки Git, URL, file и npm aliases
считаются неподдерживаемыми. Метаданные пакета запрашиваются один раз
за запуск.

В тестовом режиме `--repository` указывает на JSON со словарём смежности.
Имена состоят из заглавных латинских букв. У каждой вершины должна быть
своя запись, даже если её список зависимостей пуст. Например:

```json
{"A": ["B"], "B": []}
```

### Что добавилось

- `src/graph.py` — `load_test_graph` проверяет локальный файл, `bfs`
  собирает достижимые узлы и рёбра для обоих источников.
- `src/registry.py` — `npm_neighbors` разрешает зависимости и кеширует
  метаданные в памяти.
- `src/versions.py` — `parse_requirement` разбирает ограничения,
  `select_version` выбирает версию.
- `examples/graphs.json` — ветвление, общая зависимость, цикл и
  изолированная вершина. Тесты графа и версий находятся в `tests/`.

### Примеры запуска

```sh
# Ветвление A -> B, A -> C и общая зависимость D с продолжением до E
./run.sh --package A --test-mode --repository examples/graphs.json

# Цикл F -> G -> F
./run.sh --package F --test-mode --repository examples/graphs.json

# Изолированная вершина H
./run.sh --package H --test-mode --repository examples/graphs.json

# Реальный npm-пакет с транзитивными зависимостями
./run.sh --package chalk --version 4.1.2
```

```text
chalk@4.1.2 -> ansi-styles@4.3.0
chalk@4.1.2 -> supports-color@7.2.0
ansi-styles@4.3.0 -> color-convert@2.0.1
supports-color@7.2.0 -> has-flag@4.0.0
color-convert@2.0.1 -> color-name@1.1.4
```

При некорректном файле, неизвестной вершине, ошибке реестра или отсутствии
подходящей версии выводится сообщение в stderr, код завершения — 1.
Ошибки аргументов по-прежнему дают код 2.

## Этап 4. Обратные зависимости

В коммите этапа 4 параметр `--reverse TARGET` выводил пакеты, которые
зависят от `TARGET` напрямую или через другие пакеты. Функция
`reverse_dependencies` из `src/graph.py` разворачивает рёбра и обходит
их тем же BFS. Сначала выводятся ближайшие зависимые пакеты. Каждый
пакет выводится один раз, сама цель исключается даже при цикле.

В тестовом режиме область поиска — весь JSON, включая вершины вне
компоненты `--package`. В сетевом режиме область ограничена графом
указанного корневого пакета, а цель задаётся как `имя@точная-версия`.
Параметр `--package` обязателен в обоих режимах.

### Примеры запуска

```sh
# B и C зависят от D напрямую, A зависит от D через них
./run.sh --package A --test-mode --repository examples/graphs.json --reverse D
```

```text
B
C
A
```

```sh
# F и G вне компоненты A, но поиск идёт по всему тестовому репозиторию
./run.sh --package A --test-mode --repository examples/graphs.json --reverse F

# Изолированная вершина: «Обратных зависимостей нет.»
./run.sh --package A --test-mode --repository examples/graphs.json --reverse H

# Неизвестная вершина: сообщение в stderr и код 1
./run.sh --package A --test-mode --repository examples/graphs.json --reverse Z
```

## Этап 5. Визуализация

DGVT сохраняет ориентированный граф в DOT и вызывает [Graphviz][] для
отрисовки SVG. Оба файла попадают в `output/`, их имена соответствуют
корневому узлу. DGVT печатает пути и открывает SVG в браузере.

При `--ascii` в терминале дополнительно печатается дерево. Отступы
показывают вложенность. Метка `[cycle]` означает ссылку на предка,
`[seen]` — ссылку на уже показанную ветвь. Такие ветви не раскрываются
повторно. Параметр `--reverse` доступен в коммите этапа 4.

В `src/visualization.py` функция `to_dot` формирует DOT, `ascii_tree`
строит дерево, `render_graph` сохраняет DOT и SVG, а `open_graph`
открывает результат. Если `dot` отсутствует или завершается с ошибкой,
CLI объясняет причину и возвращает код 1. Если не удалось открыть
браузер, SVG остаётся на диске, а CLI печатает путь для ручного
открытия и возвращает код 1.

### Примеры запуска

```sh
dot -V
./run.sh --package is-number --version 7.0.0 --ascii
./run.sh --package is-odd --version 3.0.1 --ascii
./run.sh --package chalk --version 4.1.2 --ascii
```

Пример дерева для `chalk@4.1.2`:

```text
chalk@4.1.2
|-- ansi-styles@4.3.0
|   +-- color-convert@2.0.1
|       +-- color-name@1.1.4
+-- supports-color@7.2.0
    +-- has-flag@4.0.0
```

### Сравнение с npm

Каждый пакет проверен отдельно с npm 10.9.4. Установку для сравнения
выполняли во временных каталогах с отключёнными скриптами. Чтобы
повторить проверку:

```sh
for package in is-number@7.0.0 is-odd@3.0.1 chalk@4.1.2; do
    (
        cd "$(mktemp -d)" || exit 1
        npm init -y > /dev/null &&
        npm install --ignore-scripts --no-audit --no-fund --omit=dev \
            --save-exact "$package" &&
        npm ls --all --omit=dev
    )
done
```

Сравнивали вершины с точными версиями и направленные рёбра SVG с
поддеревом установленного пакета из [`npm ls --all`][npm-ls].
Верхний узел временного проекта в выводе npm относится к среде
проверки. DGVT начинает дерево сразу с анализируемого пакета.

| Пакет | Вершины | Рёбра | Сравнение с npm |
| --- | ---: | ---: | --- |
| `is-number@7.0.0` | 1 | 0 | Совпало |
| `is-odd@3.0.1` | 2 | 1 | Совпало |
| `chalk@4.1.2` | 6 | 5 | Совпало |

Проверка относится к этим трём пакетам. DGVT читает обычное поле
`dependencies` и выбирает версии по опубликованным диапазонам.
npm учитывает также другие типы зависимостей и правила установки.

[Graphviz]: https://graphviz.org/doc/info/command.html
[npm-ls]: https://docs.npmjs.com/cli/commands/npm-ls/

## Тесты

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тесты проверяют CLI, ответы реестра, границы диапазонов версий,
локальные графы, циклы, DOT, ASCII и ошибки визуализации. В тестах
ответы реестра, Graphviz и открытие браузера подменяются.
