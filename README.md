## Общее описание

DGVT принимает имя npm-пакета и параметры анализа зависимостей.
Этапы работы зафиксированы отдельными коммитами.

## Установка и запуск

Для запуска нужны Python 3.10+ и оболочка sh. Сборка не требуется.

Из корня проекта:

```sh
./run.sh --help
./run.sh --package is-odd --version 3.0.1
```

## Этап 1. Минимальный CLI и конфигурация

На первом этапе приложение проверяло параметры и печатало конфигурацию.
Вывод конфигурации относится к коммиту первого этапа.
Для URL проверялся формат адреса, для тестового файла — читаемость.

### Структура проекта на этапе 1

```text
.
├── README.md
├── .gitignore
├── run.sh                    # запуск CLI
├── requirements-dev.txt      # pytest
├── src/
│   └── main.py                # разбор аргументов, проверки и вывод
├── examples/
│   └── repository.json       # пример локального репозитория
└── tests/
    └── test_cli.py            # проверки через run.sh
```

### Параметры

| Параметр | Назначение |
| --- | --- |
| `--package NAME` | Обязательное имя пакета, например `is-odd` или `@scope/pkg`. В тестовом режиме — только буквы A–Z. |
| `--repository SOURCE` | Базовый HTTP(S)-адрес без учётных данных, запроса и фрагмента. По умолчанию `https://registry.npmjs.org`. В тестовом режиме обязателен путь к читаемому файлу. |
| `--test-mode` | Переключает источник на локальный тестовый файл. |
| `--version VERSION` | Точная версия npm-пакета, обязательна в сетевом режиме. С `--test-mode` не используется. |
| `--ascii` | Флаг вывода ASCII-дерева. На этапе 1 выводится его значение. |

### Примеры работы

```sh
./run.sh --package is-odd --version 3.0.1 --ascii
```

```text
package=is-odd
repository=https://registry.npmjs.org
test_mode=false
version=3.0.1
ascii=true
```

```sh
./run.sh --package A --test-mode --repository examples/repository.json
```

```text
package=A
repository=examples/repository.json
test_mode=true
version=
ascii=false
```

### Обработка ошибок

При неверных параметрах приложение печатает сообщение в stderr и
завершается с кодом 2. Успешный запуск завершается с кодом 0.

```sh
./run.sh --version 3.0.1                                  # нет имени пакета
./run.sh --package 'Bad Name' --version 3.0.1              # неверное имя
./run.sh --package is-odd                                 # нет версии
./run.sh --package is-odd --version '^3.0.1'               # диапазон версий
./run.sh --package is-odd --version 3.0.1 --repository ftp://example.org
./run.sh --package A --test-mode                          # нет пути к файлу
./run.sh --package A --test-mode --repository missing.json
./run.sh --package is-odd --version 3.0.1 --test-mode=true # флаг без значения
./run.sh --package is-odd --version 3.0.1 --ascii=true     # флаг без значения
```

## Этап 2. Прямые зависимости npm

CLI запрашивает JSON-метаданные пакета по адресу из `--repository` и
читает поле `dependencies` указанной версии. Каждая строка содержит
имя зависимости и её ограничение версии. Строки отсортированы по имени.
Для пакета без зависимостей выводится сообщение «Прямых зависимостей нет.».

Настройки CLI описаны в этапе 1. Сетевые запуски требуют доступа к реестру.
Тестовый режим не поддерживается. Параметр `--ascii` не меняет вывод.

### Структура проекта на этапе 2

К структуре этапа 1 добавились два файла:

- `src/registry.py` — `fetch_metadata` запрашивает и разбирает JSON,
  `get_dependencies` выбирает нужную версию и возвращает её зависимости.
- `tests/test_registry.py` — тесты чтения метаданных с подменой ответа.

### Примеры запуска

```sh
./run.sh --package is-odd --version 3.0.1
```

```text
is-number ^6.0.0
```

```sh
./run.sh --package is-number --version 7.0.0
```

```text
Прямых зависимостей нет.
```

### Обработка ошибок

Отсутствующий пакет или версия, ошибка HTTP или соединения, тайм-аут
и неверный ответ реестра дают сообщение в stderr и код завершения 1.
Ошибки параметров по-прежнему дают код 2.

```sh
./run.sh --package is-odd --version 999.0.0
```

```text
DGVT: версия is-odd@999.0.0 не найдена
```

## Тесты

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тесты проверяют параметры CLI, выбор точной версии, чтение зависимостей
и обработку ошибок реестра. Ответы реестра подменяются в тестах, поэтому
для их запуска интернет не нужен.
